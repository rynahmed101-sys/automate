# Self-Improvement Architecture

Automate is being extended from an autonomous development machine into an evidence-driven self-improving system.

## Learning loop

Action → observation → durable experience → historical comparison → candidate lesson → reproduction/generalization → independent verification → adoption → future behavior change.

Raw experience is evidence. It is not permission to change behavior.

## Memory

The learning store separates:

- execution experiences;
- lessons and their explicit lifecycle;
- strategy evidence;
- discovered capability candidates;
- system-evolution proposals and bounded change plans.

Important failures can become regression obligations. Repeated successes can become candidate strategy lessons. Neither is adopted automatically.

## Strategy learning

A historical strategy can replace the default only when:

1. an explicit strategy lesson is ADOPTED;
2. enough historical attempts exist;
3. the conservative success bound clears the configured threshold.

This prevents one lucky run from becoming policy.

## Scientific discovery

THE MIRROR may produce `mirror.research_proposal.v1` candidates. Automate stores and triages them without mutating the canonical capability inventory. Verification and normal capability promotion remain separate.

## Self-evolution

An adopted system-improvement lesson can produce a mutable evolution proposal. A proposal becomes executable only after verification, regression evidence, an exact base revision, and a bounded path allowlist.

The executor can create one atomic Git commit and open a normal PR to `main`. It never merges itself and never marks certification.

## Constitutional boundary

The deepest authority/epistemic rules are classified separately. Governance or constitutional changes are never automatically promoted.

The goal is not a machine that always agrees with its original designers. The goal is a machine that can change its methods when evidence justifies change, while preserving provenance, uncertainty, reversibility, and adversarial verification.


## Shared-memory synchronization

When Chanfana's durable learning service is configured, Automate may synchronize recent experiences and lessons before strategy selection and publish newly recorded artifacts afterward. Remote availability is not a prerequisite for the local learning path.

The cross-repository service remains a transport layer. Automate validates incoming artifacts against its own contracts before they can affect local learning state.
