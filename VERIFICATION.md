# Verification Standards & Soundness in Automate (v0.2)

Automate adheres to a philosophy of strict verification hygiene. We reject the paradigm where an AI model claims a derivation is "correct" or "proved" without independent, machine-auditable verification certificates.

---

## 1. Multiple Verification Authorities

Different aspects of mathematical physics require different verification disciplines:

| Domain | Authority | Verification Criteria | Status Assigned |
| :--- | :--- | :--- | :--- |
| **Formal Theorems** | Lean 4 | Type-theoretic proof checking with Lean 4 kernel (zero `sorry` axioms) | `FORMALLY_PROVED` |
| **Algebra & Calculus** | SymPy | Direct symbolic differentiation, zero-testing $(A - B == 0)$, variational Euler-Lagrange | `SYMBOLIC_CHECKED` |
| **Differential Equations** | SciPy | Numerical IVP integration, energy conservation drift $\Delta E / E_0 < 10^{-6}$ | `NUMERICALLY_CHECKED` |
| **Empirical Validation** | SciPy | Non-linear regression, $R^2 > 0.90$, reduced $\chi^2 \in [0.5, 2.0]$, parameter covariance | `STATISTICALLY_CHECKED` |
| **Dimensional Analysis** | Automate IR | Base SI dimension algebra homogeneity $[M]^a [L]^b [T]^c$ across all terms | `DIMENSIONALLY_CHECKED` |
| **Graph Topology** | Automate Core | Acyclic DAG topology and node identifier integrity via Kahn's algorithm | `STRUCTURALLY_VALID` |
| **Untrusted AI Proposals** | Automate AI | Candidate transformations generated by an LLM or heuristic | `AI_PROPOSED` (Strictly Unverified) |

For in-depth analysis of why collapsing these into a scalar percentage is mathematically dishonest, see [Verification Model & Status Taxonomy](docs/VERIFICATION_MODEL.md).

---

## 2. Integrity Rules

1. **AI Proposes, Backends Verify**:
   Any step proposed by an AI model enters the graph tagged strictly as `AI_PROPOSED`. It is never treated as verified until an independent backend executes and succeeds.
2. **No Silent Assumption Drops**:
   If a theorem depends on $m > 0$ or vanishing boundary terms, that assumption remains bound to all downstream conclusions. Dropping the assumption invalidates the downstream subgraph.
3. **Lean Proof Failures are Legitimate**:
   If Lean 4 returns a non-zero exit code or compilation error, the status is set to `FAILED`. It is never recorded as "probably correct".
4. **Statistics Do Not Prove Mathematics**:
   Fitting noisy experimental data validates empirical agreement; it never upgrades a mathematical hypothesis to `FORMALLY_PROVED`.
5. **Lossless Multi-Artifact Packages**:
   Automate exports complete certificate packages (`certificate.json`, `assumptions.json`, `obligations.json`, `evidence.json`, `subgraph_expansion.json`, `provenance.json`) governed by a root `manifest.json` containing SHA-256 hashes of every artifact.
6. **Sandboxed Subprocess Execution**:
   Lean code and numerical scripts are executed in isolated temporary scratch directories with execution timeouts to prevent runaway processes.
